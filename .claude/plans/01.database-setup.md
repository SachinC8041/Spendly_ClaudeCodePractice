# Plan: Database Setup

Source spec: `.claude/specs/01.database-setup.md`. Branch: `feature/database-setup`.

## Context

Spendly's data layer is nearly complete — `User` and `Expenses` entities exist, Hibernate manages
the schema with `ddl-auto=update`, and the repositories and `PasswordEncoder` bean are already
wired. Three gaps remain before any feature work (auth, profile, expense tracking) can build on it:

1. `Expenses` has no `created_at` column, so there is no record of when a row was entered.
2. There is no demo data, so a fresh clone has nothing to log in with and no expenses to render.
3. `application.properties` carries a typo that silently blanks the application name, plus two
   `sql.init` keys that do nothing in this project.

Outcome: a clean start on a fresh `speendly` schema produces a working demo account
(`demo@spendly.com` / `demo123`) with 8 expenses totalling 5389.25, and restarts add nothing.

Verified against the code before planning: `Expenses.java` lacks `createdAt`; `User.createdAt`
already exists in the required form; `UserRepository.findByEmail` and
`ExpenseRepository.findByUserOrderByDateDesc` exist; `ProjectConfig.passwordEncoder()` is a
delegating encoder (so hashes are `{bcrypt}`-prefixed); `pom.xml` already has
`spring-boot-starter-data-jpa` and `-security`, so **no new dependencies**.

## Changes

### 1. `src/main/java/com/example/speendlyclaude/model/Expenses.java` — add `createdAt`

Add below the existing `description` field:

```java
@Column(nullable = false, updatable = false)
@ColumnDefault("CURRENT_TIMESTAMP(6)")
private Instant createdAt = Instant.now();
```

New imports: `org.hibernate.annotations.ColumnDefault`, `java.time.Instant`.

`@ColumnDefault` is load-bearing here (unlike on `User.createdAt`): without a DB-level default,
`ALTER TABLE` adding a NOT NULL datetime to a table that already has rows fails with MySQL 1292,
and `ddl-auto=update` only *logs* that failure — the app starts and then every expense query
breaks on the missing column.

Leave `@Table(name = "Expenses")`, the `expense_date` column name, and the `date` field name
exactly as they are. The class's existing `@RequiredArgsConstructor` stays — with no final fields
it still yields the no-arg constructor JPA needs.

### 2. `src/main/resources/application.properties` — cleanup

- Line 1: `/spring.application.name=...` → `spring.application.name=speendlyclaude` (drop the
  stray `/`; it is not a comment marker in `.properties`, so the key is currently unset).
- Delete `spring.jpa.defer-datasource-initialization=true` and `spring.sql.init.mode=always` —
  both only affect `schema.sql`/`data.sql`, which this project does not use.
- Leave the datasource env-var block, `ddl-auto=update`, `show-sql`, `format_sql`, and
  `devtools.restart.enabled` untouched.

### 3. `src/main/java/com/example/speendlyclaude/config/DataSeeder.java` — new

`@Component` implementing `CommandLineRunner`, in package `com.example.speendlyclaude.config`,
with `@RequiredArgsConstructor` injecting `UserRepository`, `ExpenseRepository`, `PasswordEncoder`.
`run(String... args)` is `@Transactional` so a mid-way failure cannot leave a demo user with no
expenses.

Logic:

1. `userRepository.findByEmail("demo@spendly.com").isPresent()` → return early.
   Use the email check, **not** `count() > 0` — a DB holding unrelated test accounts would
   otherwise skip seeding forever and never create the demo user.
2. Save the demo user: name `Demo User`, email `demo@spendly.com`,
   `passwordHash = passwordEncoder.encode("demo123")`.
3. Build the 8 expenses below against that user and persist with `expenseRepository.saveAll(...)`.

Dates come from `YearMonth.now().atDay(day)` (every month has a day 26, so this never throws).
Amounts are `new BigDecimal("450.00")` — from strings, never doubles. Use setters only, no builders.

| Day | Category | Amount | Description |
| --- | --- | --- | --- |
| 2 | Food | 450.00 | Lunch with team |
| 4 | Transport | 120.00 | Metro card top-up |
| 6 | Bills | 1850.50 | Electricity bill |
| 10 | Health | 600.00 | Pharmacy |
| 14 | Entertainment | 499.00 | Movie tickets |
| 18 | Shopping | 1299.00 | Running shoes |
| 22 | Other | 250.00 | Birthday gift |
| 26 | Food | 320.75 | Weekly groceries |

7 distinct categories, total 5389.25. Do not catch exceptions — let a failure roll back and stop
startup loudly. No profile restriction (`@Profile("dev")`) in this step; the spec calls that out as
a pre-deployment task since the demo password is public.

Startup order needs no wiring in `SpeendlyclaudeApplication.java`: component scan finds the class,
Hibernate applies DDL first, then the context finishes, then `run()` fires. `CommandLineRunner` is
used rather than `data.sql` because the latter cannot call `PasswordEncoder`.

### 4. `CLAUDE.md` — document the new class

Add a `config/DataSeeder.java` bullet to the Architecture section, next to the existing
`config/ProjectConfig.java` entry.

Not changed: `ExpenseController` (new expenses get `createdAt` from the field initializer),
`UserController`, templates, `pom.xml`, and the test class.

## Verification

Confirmed with you: I run the full check against your local MySQL. Requires MySQL up and the
`speendly` schema to exist (Hibernate creates tables, not the schema).

1. `.\mvnw.cmd clean package` — compiles, confirms Lombok/annotation wiring.
2. `.\mvnw.cmd spring-boot:run` — watch the log for the `alter table expenses add column created_at`
   statement on first start, and treat **any** `Error executing DDL` line as a failure, not a warning.
   Confirm the seeder runs without error.
3. Restart once — confirm no second demo user and no duplicate expenses.
4. In the MySQL console, run the checks from spec section 14: `SHOW CREATE TABLE expenses`
   (expect `created_at` with `DEFAULT CURRENT_TIMESTAMP(6)` and an FK to `users(id)`),
   `SHOW CREATE TABLE users` (expect `UNIQUE KEY` on `email`), the demo-user row with a
   `{bcrypt}` hash prefix, and the aggregate returning `8, 7, 5389.25`.
5. Run the two negative inserts from section 14 — expect MySQL 1062 (duplicate email) and
   1452 (invalid `user_id`).
6. Log in at `/login` as `demo@spendly.com` / `demo123` → lands on `/expenses` showing 8 rows
   and a ₹5389.25 total.
7. `.\mvnw.cmd test` — passes. (`@SpringBootTest` also triggers the seeder against the same
   database; the email check keeps that idempotent.)

No new test is added, per your choice — `contextLoads()` stays the only test, and seed data is
verified by the SQL above.

## Out of scope

Flyway/Liquibase or any migration files, H2 or a separate test database, a service layer, making
`category` an enum or a form dropdown, and gating `DataSeeder` behind a dev profile.
