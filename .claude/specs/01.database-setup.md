# Spec: Database Setup (Spring Boot)

## 1. Overview

Finish the data layer for Spendly and load demo data on startup.

This is the Spring Boot version of the original Python/SQLite spec. Most of the schema already exists as JPA entities, so three things are left:

1. Add the missing `created_at` column to `Expenses`.
2. Seed one demo user and 8 sample expenses on startup.
3. Clean up `application.properties`.

All future features (authentication, profile, expense tracking) depend on this being correct.

Stack: Spring Boot 4.1.0, Java 21, Spring Data JPA (Hibernate), MySQL 8, Spring Security, Lombok.

## 2. Depends on

Nothing. This is the first step.

MySQL must be running and the `speendly` schema must exist. Hibernate creates tables inside the schema, but not the schema itself.

## 4. Database Schema

Hibernate generates the tables from the entities (`ddl-auto=update`), so the entity classes are the schema. There are no SQL files.

---

### A. users: `model/User.java` (complete, no changes)

| Column | MySQL type | Java field | Constraints |
| --- | --- | --- | --- |
| id | BIGINT | `Long id` | Primary key, auto-increment |
| name | VARCHAR(255) | `String name` | Not null |
| email | VARCHAR(255) | `String email` | Unique, not null |
| password_hash | VARCHAR(255) | `String passwordHash` | Not null |
| created_at | DATETIME(6) | `Instant createdAt` | Not null, not updatable, set by `Instant.now()` |

---

### B. expenses: `model/Expenses.java` (add `created_at`)

| Column | MySQL type | Java field | Constraints |
| --- | --- | --- | --- |
| id | BIGINT | `Long id` | Primary key, auto-increment |
| user_id | BIGINT | `User user` | Foreign key → users.id, not null, lazy `@ManyToOne` |
| amount | DECIMAL(12,2) | `BigDecimal amount` | Not null |
| category | VARCHAR(40) | `String category` | Not null |
| expense_date | DATE | `LocalDate date` | Not null |
| description | VARCHAR(255) | `String description` | Nullable |
| created_at | DATETIME(6) | `Instant createdAt` | **To add.** Not null, not updatable, defaults to the current time |

Add this field below `description`:

```java
@Column(nullable = false, updatable = false)
@ColumnDefault("CURRENT_TIMESTAMP(6)")
private Instant createdAt = Instant.now();
```

Imports: `org.hibernate.annotations.ColumnDefault` and `java.time.Instant`.

`@ColumnDefault` is required, even though `User.createdAt` does not have it. Without a default, adding a NOT NULL datetime column to a table that already has rows fails with MySQL error 1292. `ddl-auto=update` only logs that failure as a warning, so the app still starts, and then every expense query fails because the column is missing.

Intentional differences from the Python spec:

- `amount` is `DECIMAL(12,2)`, not a float, so money stays exact.
- `date` is a real `DATE`, not text.
- The date column is `expense_date`. Keep this name. The Java field stays `date`.
- `@Table(name = "Expenses")` stays as it is. MySQL on Windows stores the name as `expenses`.

### `DataSeeder` (replaces `seed_db()`)

- Package: `com.example.speendlyclaude.config`
- `@Component` that implements `CommandLineRunner`, so Spring calls `run()` once on every startup
- `@RequiredArgsConstructor` to inject `UserRepository`, `ExpenseRepository` and `PasswordEncoder`
- `run()` is `@Transactional`, so a failure can't leave a demo user with no expenses

Logic:

1. Call `userRepository.findByEmail("demo@spendly.com")`. If a user is found, return early.
2. Create and save the demo user:
    - name: Demo User
    - email: demo@spendly.com
    - password: `passwordEncoder.encode("demo123")`
3. Create the 8 expenses below, all linked to the demo user, and save them with `saveAll`.

Check for the demo email, not `userRepository.count() > 0`. The database may already hold test accounts, and a count check would then skip seeding and never create the demo user.

Sample expenses:

| Day of month | Category | Amount | Description |
| --- | --- | --- | --- |
| 2 | Food | 450.00 | Lunch with team |
| 4 | Transport | 120.00 | Metro card top-up |
| 6 | Bills | 1850.50 | Electricity bill |
| 10 | Health | 600.00 | Pharmacy |
| 14 | Entertainment | 499.00 | Movie tickets |
| 18 | Shopping | 1299.00 | Running shoes |
| 22 | Other | 250.00 | Birthday gift |
| 26 | Food | 320.75 | Weekly groceries |

- This covers all 7 categories and adds up to 5389.25.
- Build each date with `YearMonth.now().atDay(day)`. Every month has a day 26, so this always works.
- Dates later in the month may be in the future. That is fine for demo data.

## 6. Startup Wiring 

No changes to `SpeendlyclaudeApplication.java`. Component scanning finds `DataSeeder` automatically.

Startup order:

1. Hibernate applies `ddl-auto=update` to the schema.
2. The application context finishes starting.
3. Spring calls `DataSeeder.run()`.

Use `CommandLineRunner`, not `data.sql`. A `data.sql` script can't call `PasswordEncoder`, and with `spring.sql.init.mode=always` it would run on every startup.

## 11. Rules for Implementation

- Use Spring Data JPA for all database access. This replaces the Python rule against ORMs
- No `JdbcTemplate` and no raw `Connection`
- Use derived repository methods first. If a custom query is needed, use `@Query` with named parameters
- Never build JPQL or SQL with string concatenation
- `amount` is always `BigDecimal`. Create values from strings, such as `new BigDecimal("450.00")`, never from a `double`
- Dates are `LocalDate`, which displays as `yyyy-MM-dd`
- Hash passwords only through the `PasswordEncoder` bean. Do not hard-code a hash
- Use Lombok `@Getter` and `@Setter` on entities, with no builders, as in `CLAUDE.md`
- `DataSeeder` must never create duplicates
- Keep `ddl-auto=update` and do not add migration files

## 12. Expected Behavior

- First start after this change:
    - Hibernate adds `created_at` to `expenses`, and `show-sql=true` prints the `alter table`
    - Any existing `expenses` rows stay intact and get the time of the `ALTER TABLE` as `created_at`
- Later starts leave the schema unchanged
- `DataSeeder` inserts the demo data once, and restarts add nothing
- New expenses get `createdAt` from the field initializer, so `ExpenseController` does not change
- `@SpringBootTest` also runs `DataSeeder`, against the same database, and the email check keeps that safe

## 13. Error Handling Expectations

| Situation | MySQL error | What should happen |
| --- | --- | --- |
| Duplicate email | 1062 | Insert fails, Spring raises `DataIntegrityViolationException` |
| Expense with invalid `user_id` | 1452 | Insert fails, Spring raises `DataIntegrityViolationException` |
| Exception inside `DataSeeder` | Depends on the cause | Do not catch it. The transaction rolls back and startup stops with a clear error |
| Invalid repository method or `@Query` | None | App fails at startup with a clear error |
| `ddl-auto` can't change a table | Depends on the cause | Hibernate logs a warning and the app keeps starting. Treat any `Error executing DDL` line as a failure |

## 14. Definition of Done

- [ ] App starts with no errors and no `Error executing DDL` warning
- [ ] `expenses` has `created_at` and a foreign key to `users`
- [ ] `users.email` is unique
- [ ] Demo user exists with a hashed password
- [ ] 8 sample expenses exist across all 7 categories, totalling 5389.25
- [ ] Restarting the app adds no duplicate data
- [ ] Logging in at `/login` with `demo@spendly.com` / `demo123` opens `/expenses`, with 8 rows and a total of ₹5389.25
- [ ] Both invalid inserts below are rejected
- [ ] `.\mvnw.cmd test` passes

Run these in the IntelliJ database console:

```sql
USE speendly;

-- Expect created_at with DEFAULT CURRENT_TIMESTAMP(6), and a FOREIGN KEY to users (id)
SHOW CREATE TABLE expenses;

-- Expect UNIQUE KEY on email
SHOW CREATE TABLE users;

-- Expect 1 row with hash_prefix {bcrypt}
SELECT name, email, LEFT(password_hash, 8) AS hash_prefix
FROM users
WHERE email = 'demo@spendly.com';

-- Expect 8, 7, 5389.25
SELECT COUNT(*) AS expense_count,
       COUNT(DISTINCT e.category) AS category_count,
       SUM(e.amount) AS total
FROM expenses e
JOIN users u ON u.id = e.user_id
WHERE u.email = 'demo@spendly.com';

-- Expect ERROR 1062 (duplicate email)
INSERT INTO users (name, email, password_hash, created_at)
VALUES ('Copy', 'demo@spendly.com', 'x', NOW(6));

-- Expect ERROR 1452 (invalid user_id)
INSERT INTO expenses (user_id, amount, category, expense_date)
VALUES (999999, 1.00, 'Food', CURDATE());
```
